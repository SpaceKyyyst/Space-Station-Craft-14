# Правила работы с Git

## Ветки

1. Одна задача — отдельная ветка `ShinozakiAichi/<название-задачи>`.
2. Новую ветку создавать от актуального `main`.
3. Не смешивать в одной ветке несвязанные задачи.

## Коммиты

1. Одна небольшая завершённая подзадача — отдельный коммит.
2. Не переписывать опубликованную историю без отдельного указания.
3. Коммит описывать на русском и английском: сначала раздел `RU`, затем `EN`.
4. Сообщение должно отражать только фактические изменения, их причину и проверки.

## Pull request

1. После проверок отправлять ветку на fork и создавать PR в основной репозиторий.
2. Описание PR писать на русском и английском: сначала `RU`, затем `EN`.
3. В описании указывать изменения, затронутые области, способ проверки, ограничения и риски.
4. Перед созданием или обновлением PR проверять diff, тесты, CI и конфликты.
5. К каждой PR добавлять существующие labels из репозитория согласно фактическому diff. Дополнительные labels добавлять только при необходимости; не создавать случайные или неподходящие labels.
6. После создания PR прикреплять её к текущей задаче.
7. Не сливать PR без проверки diff, тестов и CI.

## Fork и публикация

1. Коммиты отправлять на удалённый fork пользователя `ShinozakiAichi`.
2. Перед push проверять имя ветки, удалённую ветку и целевой репозиторий.
3. Для конфликтов сохранять чужие изменения и не использовать переписывание опубликованной истории.

## Локальные файлы

Не публиковать в Git `SUPERPOWERS`, навыки, личные инструкции, служебные планы, секреты, кэш, логи, отчёты, видео, скриншоты и результаты сборки. Исключение из Git не должно удалять локальные оригиналы.
