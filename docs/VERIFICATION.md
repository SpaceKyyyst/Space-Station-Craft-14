# Проверки и непрерывная интеграция

## Локальные проверки

```powershell
.\gradlew.bat domainTest
.\gradlew.bat checkstyleMain
.\gradlew.bat build
.\gradlew.bat -I config/gameplay-tests.init.gradle runGameplayTest
```

На Linux/macOS используется `sh ./gradlew` с теми же именами задач.

| Проверка | Что покрывает | Результат |
| --- | --- | --- |
| `domainTest` | Индексы газов, броня, реакции, газообмен и тепловой баланс, распределение объёма/энергии, очередь задач и JFR-события | `build/reports/tests/domainTest/index.html` |
| `checkstyleMain` | `GasType`, `GasReaction`, пакеты `combat`, `atmosphere`, `chemistry`, `math` | `build/reports/checkstyle/main.html` |
| `build` | Компиляция всего мода, тесты, Checkstyle, упаковка | `build/libs/` |
| `runGameplayTest` с init script | Серверные блоки, команды, реагенты, анализатор, границы регионов, бюджет ячеек, вложенные карты, локальная пересборка электросети | `build/gameplay-tests/run/results.xml` |

Доменный набор содержит 23 теста. Эти исходники компилируются без Minecraft-зависимостей из тех же файлов, которые используются при сборке мода.

Серверные тесты находятся в `src/gameTest`. Init script использует отдельный
каталог сборки и подключает тестовые классы только к диагностическому запуску.
JAR из `build/gameplay-tests` не предназначен для распространения; релиз создаётся
обычным `build`. Серверный набор проверяет также пять реально зарегистрированных
контейнеров; отсутствующие запланированные предметы не входят в конфигурацию ёмкостей.

Checkstyle пока охватывает выделенный домен, а не весь сгенерированный код. При добавлении независимой подсистемы её исходники включаются в `sourceSets.domain` в `build.gradle`; тесты размещаются в `src/domainTest/java`.

## Проверки инфраструктуры

Для Python-скриптов требуется Python 3.11 или новее:

```sh
python .github/scripts/test_checks.py
python .github/scripts/check_project.py
python .github/scripts/check_resources.py
bash .github/scripts/test-release.sh
```

Первая команда проверяет CI-скрипты и формирование аннотаций. Вторая сверяет версию,
mod ID и наличие файлов сборки. `check_resources.py` проверяет модели, достижимые
из определений предметов и состояний блоков, и используемые ими текстуры: грани,
слои предметов, частицы, наследование и циклические ссылки. Внешние ресурсы
Minecraft и других модов не проверяются. Проверка не заменяет просмотр рендера.
Последняя команда проверяет публикацию на подставном `gh`:
отсутствие и неоднозначность JAR, контрольную сумму, повторный запуск, восстановление
черновика и несовпадение целевого коммита. Она не создаёт настоящие релизы.

## GitHub Actions

Workflow [build.yml](../.github/workflows/build.yml) выполняет проверки метаданных, тесты скриптов и полную сборку на Ubuntu 24.04 с Temurin 25. Ошибки компилятора, Checkstyle и JUnit выводятся в GitHub Checks. Журнал сборки и отчёты доступны в артефакте `test-reports`, JAR — в `mod-jar`.

Точные события запуска заданы в секции `on` workflow. Ручной запуск доступен через Actions → Build and release → Run workflow.

## Публикация релиза

Публикация выполняется отдельным заданием после успешной сборки `main`. Pull request и другие ветки не публикуют релизы.

- Загружается JAR, собранный предыдущим заданием, без повторной сборки.
- Тег содержит имя артефакта, номер запуска и короткий SHA коммита.
- В релиз добавляются JAR и `SHA256SUMS.txt`.
- Повторный запуск проверяет SHA существующего тега, обновляет артефакты и завершает публикацию оставшегося черновика.
- Если тег указывает на другой коммит, публикация завершается ошибкой.

В форке релизы создаются в самом форке. Для работы pipeline в конкретном репозитории GitHub Actions должны быть разрешены его владельцем.

## Игровое тестирование

Автоматические тесты не заменяют запуск Minecraft. Сценарии зависят от изменённой подсистемы:

| Область | Что проверить в игре |
| --- | --- |
| Загрузка мода | Клиент и выделенный сервер с обязательными зависимостями |
| Сохранения | Сохранение и повторная загрузка тестового мира |
| Броня | Пустые слоты, разные предметы Curios, несколько источников сопротивления |
| Атмосфера | Пустая ячейка, нагрев/охлаждение, расход и образование газов |
| Энергетика | Соединение и разрыв кабелей, несколько источников, выгрузка чанков |
| Сеть и интерфейс | Несколько игроков, синхронизация, недопустимые действия клиента |

Успешный CI подтверждает только выполненные автоматические проверки. Игровые результаты следует оценивать для конкретной версии и набора изменений.
