# Проверки первого этапа рефакторинга

## Автоматические проверки

- `domainTest`: 16 тестов — стабильность индексов газов, шесть проверок правил
  брони, девять проверок реакций (копирование массивов, валидация, границы,
  стехиометрия, тепло, отсутствие частичной мутации).
- Шесть тестов газовых реакций воспроизвели дефекты исходного кода до исправления.
- `checkstyleMain`: анализ чистого домена; весь остальной Java-код проверяется
  компилятором в полной сборке. Это начало покрытия, а не полный статический
  аудит тысяч сгенерированных классов.
- `.github/scripts/test_checks.py`: шесть тестов CI-проверок и аннотаций.
- `.github/scripts/test-release.sh`: отсутствие/неоднозначность JAR, создание
  релиза, контрольная сумма, повторная загрузка, восстановление черновика,
  создание тега и отказ при несовпадении SHA даже без существующего релиза.
  Скрипт использует подставной `gh` и ничего не публикует.
- `build`: компиляция всего мода, доменные тесты, Checkstyle и упаковка JAR.
  На GitHub Actions используется Ubuntu и Temurin 25.

## Ограничения локальной проверки

Исходная полная сборка в Windows остановилась на декомпиляции Minecraft:
JVM не смогла выделить native memory (Windows error 1455). Исходный проект
при этом успешно собрался в GitHub Actions. Это не ошибка компиляции мода.

В локальном пути с кириллицей запуск Gradle Test Worker завершался
`ClassNotFoundException`, хотя классы были скомпилированы. Локальные тесты
выполнены с каталогом `build` вне пути с кириллицей через приватный Gradle
init script. В репозиторий абсолютные пути не добавлялись. Если проблема
повторяется, использовать checkout в коротком пути латиницей и JDK 25.

## Что ещё требует проверки в игре

Не заявляем проверенными запуск клиента/dedicated server, взаимодействие
нескольких игроков, сохранение мира, реальную экипировку Curios и длительную
атмосферную симуляцию. Перед выпуском для постоянного сервера проверить их
на копии мира. Автоматический релиз означает прошедшую сборку и тесты,
а не завершённый игровой QA.

Переписывание энергетики, миграция всех процедур MCreator и проверка сетевых
сообщений остаются отдельными этапами; риски перечислены в `ARCHITECTURE.md`.
