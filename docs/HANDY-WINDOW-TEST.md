# Первый перенос на Handy: генератор гравитации

## Границы

ПКМ по генератору открывает окно Handy без слотов инвентаря. Показатели и команды используют серверное представление LDLib2. `GravityGeneratorWindow` строит UI, проверяет доступ и адаптирует существующие показатели; `GravityGeneratorService` продолжает рассчитывать заряд и гравитацию. `GravityGeneratorBlockEntity` реализует `BlockEntityUIProvider`.

Открытие и каждая команда проверяют живого игрока, режим наблюдателя, измерение, позицию, загруженный чанк, актуальность BlockEntity и расстояние до 8 блоков. Сервер дополнительно проверяет `mayInteract`. Creative не обходит расстояние. Обновление одного окна — O(1); N открытых окон требуют O(N) работы оконного менеджера.

## Зависимости

- Minecraft 26.1.2, NeoForge 26.1.2.109.
- Присланный Handy 0.1.0 в `libs/`, контрольная сумма — в `libs/README.md`.
- LDLib2 26.1.2.39 из Modrinth, версия закреплена в Gradle.
- Handy и LDLib2 нужны на клиенте и сервере; они не включены в JAR SSC14.

## Проверка

1. Открыть окно ПКМ по генератору пустой рукой.
2. Включить и выключить питание: проверить состояние, заряд и отсутствие изменения инвентаря.
3. Переместить окно и изменить размер; проверить доступность кнопок при минимальном размере.
4. Повторить ПКМ: существующее окно должно получить фокус без дубликата.
5. Закрыть кнопкой и открыть снова; проверить актуальное состояние.
6. Отойти более чем на 8 блоков, удалить генератор, выйти из мира: окно должно потерять доступ, команды не должны менять блок.
7. Открыть два разных генератора: их команды и показатели должны оставаться независимыми.

В пилоте курсор автоматически включается, пока открыто окно Handy. После закрытия последнего окна управление возвращается камере; обычные Minecraft Screen временно получают ввод.

`GravityWindowGameTests` проверяет доступ в реальном серверном мире: обычное открытие, null, неверные измерение/позицию, расстояние, Creative и удаление блока. Визуальные сценарии требуют клиента.

Проверено 18.10.2026: compileJava, compileGameTestJava, jar и отдельный серверный ssc_14:gravity_window_access прошли. В клиенте проверены вход без пустого стартового экрана, обычные клики инвентаря, открытие генератора, включение с ростом заряда, выключение, закрытие и возврат управления камерой. Камера не вращалась при работе с кнопками. Перетаскивание, изменение размера, повторный вход с открытым окном и несколько игроков пока не проверены. Тестовый запуск использует отдельный мир Handy API Test.

## Ограничения пилота

В присланном Handy 0.1.0 `ClientGuiModeEvents.onMouseButton` безусловно отменяет обычные нажатия и отпускания мыши, в том числе вне окон. `HandyMouseCompatibility` снимает регистрацию именно объекта Method (FML регистрирует методы отдельно, не класс) и добавляет обёртку: вызывает обработчик мыши только в режиме Handy без открытого Minecraft Screen. Отпускания передаются в WindowManager.mouseReleased и удаляются из GUI_PRESSES; при открытии обычного Screen удержания сбрасываются. Дополнительный тик согласует режим курсора с наличием окна. Исходные обработчики тика/прокрутки остаются зарегистрированы один раз. Адаптер включается только для версии 0.1.0 и не снимает отмену событий, выставленную другими модами. После исправления Handy его следует удалить.

ETA использует прежнюю процедуру отображения; формула не менялась в рамках переноса. Устаревший контейнерный экран сохранён для совместимости существующих MenuProvider/регистраций, обычный ПКМ использует Handy. Следующий перенос стоит делать после проверки жизненного цикла нескольких окон и двух игроков.

## Пустой экран при входе

Handy регистрирует PlayerEvents.onPlayerLoggedIn через Consumer в конструкторе, поэтому unregister(Method) не работал. HandyStartupCompatibility отключает только фабрику RootMUI.START_UI через PlayerUIMenuType.unregister. Серверная синхронизация окон остаётся независимой. GameTest дополнен проверкой, что openUI(start_ui) возвращает false; тест и сборка JAR прошли 18.10.2026.
