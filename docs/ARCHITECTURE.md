# Архитектура проекта

Проект — мод Minecraft 26.1.2 на NeoForge 26.1.2.71, Java 25, Gradle 9.3.0.
Точка входа: `net.mcreator.ssc.Ssc14Mod`. Исходный код находится в
`src/main/java/net/mcreator/ssc`, ресурсы — в `src/main/resources`.

## Текущее устройство

| Подсистема | Основные классы | Ответственность |
| --- | --- | --- |
| Регистрация | `Ssc14Mod`, `init/*` | Идентификаторы, события, типы блоков и предметов |
| Атмосфера | `atmosphere/GasMixture`, `AtmosCell`, `AtmosphereManager`, `AtmosRegion` | Чистая симуляция, NBT-адаптер, управление регионами |
| Энергетика | `EnergyNetworkManager`, `EnergyNetwork`, `EnergySimulationServer`, `energy/EnergyTelemetry` | Топология, состояние, баланс энергии, публикация показаний |
| Химия | `chemistry/MixturePortion`, `ModReagents`, `ReagentContainerConfig` | Расчёт порции, компоненты предмета, ёмкости зарегистрированных контейнеров |
| Общая арифметика | `math/ProportionalAllocation` | Целочисленное распределение с сохранением суммы |
| Ставни | `block/ShutterController`, процедуры открытия/закрытия | Серверная анимация и совместимые точки вызова |
| Сигнальные соединения | `NetworkManager`, `NetworkSavedData`, `INetworkAction` | Сохранение связей и выполнение действий |
| Броня | `combat/ResistanceRegistry`, `ArmorResistanceHelper`, `procedures/ModArmorSetupProcedure` | Чистые правила, Curios-адаптер и настройка |
| Интерфейс | `client/*`, `world/inventory/*`, сетевые сообщения | Отрисовка, меню, синхронизация |
| Контент | `block/*`, `item/*`, `entity/*`, `procedures/*` | Игровые объекты и их обработчики |

## Направление рефакторинга

1. **Домен**: вычисления и правила без Minecraft, NeoForge и Curios.
   Новые правила группируются по подсистемам, например `combat`.
2. **Адаптеры**: чтение игрового состояния, события, сеть, NBT и вызовы домена.
   Существующие публичные фасады сохраняются для совместимости с процедурами.
3. **Композиция и контент**: регистрация объектов, настройка правил, ресурсы.

Сейчас в коде сочетаются генерируемые процедуры, игровые адаптеры и выделенные
доменные правила. Разделение ещё не охватывает все подсистемы.
Mod ID, registry ID, NBT-ключи и порядок `GasType` являются частью формата
сохранений; форматы пакетов определяют совместимость клиента и сервера.

## MCreator

`ssc_14.mcreator`, `elements/` и `models/` — часть исходного проекта.
Перед регенерацией нужно зафиксировать изменения, проверить блокировку
редактируемых элементов в MCreator и затем просмотреть весь Git diff.
Не считать Java-файл защищённым от перезаписи только из-за ручных правок.
Новая доменная логика выносится из генерируемых процедур; после генерации
необходимо повторить сборку и тесты.

## Известные риски и дальнейшие задачи

- Энергосети перестраиваются по загруженным компонентам при изменении топологии.
  Массовые изменения больших сетей могут создавать нагрузку; следующий шаг —
  индекс позиции и пересчёт только затронутых компонент с сохранением игровых тестов.
- Условия газовых реакций определяются рецептами. Разрешены зарегистрированные
  охлаждение и разложение; фактические реакции меняют результаты прежней симуляции.
- Статические кэши миров требуют проверки при выгрузке мира и повторном запуске.
- Обработчики сетевых сообщений требуют отдельной проверки дистанции,
  полномочий игрока и серверной валидации входных значений.
- README указывает AGPLv3, а `neoforge.mods.toml` — Academic Free License v3.0.
Согласование лицензионных метаданных требует решения правообладателя.

## Сложность

Пересборка кабельных компонент BFS — O(V + E), память O(V).
Поиск приборов проверяет фиксированный объём около каждого кабеля.
Кандидат на оптимизацию — индекс «позиция → сеть» после тестов разделения/слияния.
Газовая реакция проходит массив газов за O(G), где сейчас G = 10.
Для атомарного применения она использует временный массив O(G): недостаток
реагентов или переполнение не должны оставлять частично обновлённую ячейку.
Обработка брони должна занимать O(S) по числу слотов, с O(1) средним поиском
сопротивления по паре «предмет, тип урона».

Распределение порции выполняет O(G) арифметических операций и использует O(G)
памяти. Общий распределитель использует BigInteger, чтобы сумма лимитов long
не переполнялась; стоимость арифметики зависит от разрядности суммы.
Применение R газовых рецептов требует O(R × G). Управление колонной ставней
проходит O(H) блоков без рекурсивного обхода Java-стека.

## Контракты выделенного домена

`combat.ResistanceRegistry` хранит сопротивления по структурированной паре ключей.
Конечные значения ограничиваются диапазоном [0, 1], `NaN`/бесконечность
отклоняются при регистрации. Повторная регистрация заменяет только то же правило.
Несколько предметов последовательно уменьшают остаточный урон, как до рефакторинга.
`ArmorResistanceHelper` сохраняет публичный API и занимается обходом Curios.
Диагностика выполняется через `Ssc14Mod.LOGGER.debug`, без печати в stdout.

`GasReaction` копирует входные массивы и возвращает копии из accessors.
Фабрика и прямой конструктор проходят одну валидацию. Неправильные размеры
массивов — ошибка вызова; некорректные числа ячейки, недостаток вещества и
переполнение дают `false` без изменения входного состояния.
Температурные границы включительные, охлаждение ограничено 1 K.
Теплоёмкость суммируется в `double`, поэтому возможны небольшие отличия
округления от прежней арифметики `float`; формулы и рецепты сохранены.

`GasMixture` не зависит от Minecraft. `AtmosCell` сохраняет прежние методы и
NBT-ключи `m_<index>` / `temp`. Неконечные входные числа игнорируются; при
чтении сохранения некорректные значения заменяются исходными безопасными значениями.

`AtmosphereSavedData` сохраняет состав и температуру регионов отдельно для каждого
измерения в `data/ssc_14/atmosphere.dat`. В файл попадают только непустые или
нагретые/охлаждённые ячейки, включая следовые количества газа. Проницаемость
пересчитывается по блокам загруженных чанков; симуляция выгруженных чанков
приостановлена. Кэш менеджеров привязан к экземпляру мира и очищается при выходе.
Сохранение обходит O(R × 4096) ячеек для R созданных регионов; размер файла зависит
от числа изменённых ячеек. Прежние версии не записывали атмосферу, поэтому уже
потерянный до обновления газ восстановить невозможно.

Газообмен между равными объёмами переносит одинаковую долю каждой смеси в обе
стороны. Поэтому смеси перемешиваются и при равном полном давлении. Количество
каждого вещества и тепловая энергия `Σ(n × C × T)` сохраняются с точностью float;
температура вычисляется с учётом теплоёмкостей газов. Это упрощённая модель обмена,
не решение уравнений гидродинамики. Доля ограничена 0,5 за шаг. Относительный допуск
равновесия — 1e-5, абсолютный — 1e-12 моль, температурный — 0,001 К.

Очередь атмосферы обрабатывает до восьми регионов каждые четыре серверных тика,
до 256 ячеек в каждом регионе. Необработанная работа сохраняется; циклический
порядок предотвращает голодание. При превышении бюджета симуляция замедляется,
а регионы не выбрасываются. Стоимость шага ограничена O(8 × 256 × (G × R + 6G))
для G газов и R рецептов, отдельно от визуализации, загрузки и сохранения.
Ячейки создаются лениво; проницаемость рассчитывается только для обрабатываемых
ячеек и инвалидируется при изменениях блоков/чанков. Достигшие равновесия ячейки
засыпают; изменения соседей пробуждают их. Выход в пустоту происходит на границе
высоты мира, без прежнего сканирования до 40 блоков для каждой ячейки.
HUD читает атмосферу без создания регионов и пометки сохранения изменённым.

`access/IdCardRegistry` хранит типы и исходные права карт, `PlayerAccessService`
собирает разрешения из инвентаря и Curios. Тип определяется за ожидаемое O(1),
маска кэшируется до замены компонентов предмета. Процедура ID-карт остаётся
адаптером события. Аналогично `GravityGeneratorService` реализует расчёт заряда,
а старая процедура только передаёт позицию серверного блока.

`energy/EnergyTopologyService` хранит очередь изменений и индекс владельцев
кабелей. `CableDeviceMapper` определяет привязку устройств. `EnergyNetworkManager`
сохраняет совместимый API. Распределение энергии остаётся в `EnergySimulationServer`.

Пересборка выполняется порциями на серверном потоке. Сервис топологии владеет
бюджетом и поколениями обхода; `EnergyNetwork` хранит готовность компонента;
симулятор пропускает неготовые сети и подтверждает отключение потребителей.
`updatePosition` не гарантирует завершение пересборки к моменту возврата.
Новое поколение становится готовым после обхода и обработки отключения старых
компонентов. Публичный список сетей доступен только для чтения.
Рецепты атмосферы вынесены в `atmosphere/AtmosphereReactions`, адресная отправка
частиц — в `visual/GasVisualDispatcher`.

`scheduling/TickTaskQueue` не зависит от Minecraft; `ServerTaskScheduler` связывает
её с жизненным циклом сервера. Фоновая отправка задач не разрешает фоновый доступ
к миру. Подробности бюджетов, сложности и измерений описаны в
[PERFORMANCE.md](PERFORMANCE.md). Восстановление TPS при 20 игроках локально
не подтверждено.

Реестры жидкостей реагентов подключены к шине загрузки мода. Клиентский
`ReagentFluidModels` отдельно регистрирует модели NeoForge: текстуры воды с цветом
реагента. Переключение вариантов предмета переносит `DataComponentPatch`, сохраняя
пользовательские данные и базовые компоненты целевого предмета. Копирование всей
карты компонентов между вариантами недопустимо: оно переносит чужую модель и
может включить в сетевой пакет отсутствующие теги ремонта.

Энергия накопителя списывается после распределения в размере фактической передачи.
Снимки источников разделены по миру и позиции. Общая для нескольких сетей лампа
оплачивается один раз за тик; её состояние определяется объединением питающих сетей.
Текущая дискретизация лампы — 1 Дж/тик, то есть 20 Вт при 20 тиках/с.

`GasAnalyserSync` отправляет активному анализатору серверный снимок каждые пять
тиков. Пакет содержит измерение, позицию, температуру, давление и все десять газов.
Клиент не показывает снимок другой позиции/измерения или старше 20 тиков.
Новый пакет требует одинаковой версии мода на клиенте и сервере.


`energy/LampTickBatch` объединяет состояние общих потребителей на один
серверный тик. Он отвечает за чтение состояния, исключение двойной оплаты
и применение изменений света после расчёта всех LV-сетей. Снимок не переживает
тик: изменение лампы не требует отдельного протокола инвалидирования кэша.
`EnergyNetwork` дополнительно индексирует кабели по секциям для точного поиска
ближайших сетей в телеметрии. Показания мультитула публикуются раз в четыре тика.
